# GXFP51A0 FDT-down typed reply (2026-10-30, QA only)
Source: szlukabence independent WRTB-WXX9 / ST411 2020 test, https://github.com/GodsQuantum/Huawei-Matebook-13-Linux/issues/6#issuecomment-6504393291 ; related independent protocol reverse engineering https://github.com/szlukabence/goodix-fingerprint-spi-linux .
The 2020 unit replies to FDT-down 0x32 with a valid 0xB0 ACK and a separate checksum-valid 20-byte FDT report with internal tag **0x32** rather than the previously presumed 0x36. Among 72 drains, 70 had second response at 60-88ms after ACK, two missing in post-match cleanup. PR #40's 0x36-only opt-in broke 14/14.
This QA starts from rel71.74 (bacbcc3) + PR#41 pacing patch dcdb043. GXFP_FDT_DOWN_TYPED_REPLY_QA=1 activates only for sent FDT-down opcode 0x32. The driver accepts a validated 0xB0 ACK echo 0x32 with accepted status **and** one distinct 20-byte FDT response tagged 0x32 or 0x36 with wirelen=17 and checksum valid. Duplicates/unrelated frames do not count. Missing second data still fails closed, existing full session recovery follows, and the pacing fix avoids unjustified penalty. No change to 100ms wait, regular 0x36 manual FDT parser, TLS-GCM, matcher threshold 7, enrollment, PAM, GPIO, S3/S4, reset or firmware.
QA counters include only reply count, status validity, report tag, ack-report latency, 100ms window. No image/zone/template/PSK/PMK data logged.
This is not hardware validated and is not merged to main. Pegasus rollback package: /var/lib/gxfp51a0-qa-rollback/rel71.74-held-finger-QA.pkg.tar.zst SHA256 20c9ce0ee5548c033cba7619076a0ad16b8bf77e635b41a4fb1881407a27ab09. Test actual physical LOCK and inspect journal before promotion.
